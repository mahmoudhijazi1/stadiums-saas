# Platform admin: security review (DR-006, slice 7)

**Historical snapshot.** Written 2026-10-12 on branch `feat/platform-admin` after `606de23` (slices 1 to 6 and the test fixes up to `f7aa67f`). Do not rewrite this body; add a dated addendum if something changes.

**Method.**
- Read the code of the platform admin against the threats table of [DR-006](../decisions/DR-006-platform-admin.md). Every claim names a file and function.
- No code was run for this review, and no test was run: the tests named below are the ones that were written to prove each point, and they were last run green at `d8666ab` (slices 1 to 4) and `606de23` minus two files (see "Test status").
- **UNVERIFIED** marks a claim I could not trace to code or prove.
- Findings only. **No real bug was found.** The gaps below are known and recorded; nothing was fixed in this change.

## Known gaps (none fixed here)

1. **No re-hash when the password cost changes.** The owner login upgrades a hash with `passwordNeedsRehash`; `platformLogin` does not.
2. **No web reset of an owner password.** A lost first password needs the CLI `scripts/set-password.ts`. It is in DR-006's "Later" list.
3. **The per-IP login limit is inactive until `TRUSTED_CLIENT_IP_HEADER` is set**, and that needs nginx to overwrite `X-Real-IP` (a deploy precondition).
4. **Failed logins are counted but not audited.** Only successful logins and logouts write `PlatformAuditLog`.
5. **`Cache-Control: no-store` is unconfirmed in production.** The proxy sets it, but in development Next replaced it with `no-cache, must-revalidate` on the dynamic page. The RUNBOOK deploy check (`curl -I .../platform/login`) settles it; if it fails the pages need `Cache-Control` set by Next itself.
6. **No concurrent-session cap** and no web "log out everywhere".
7. **Account lockout can be used to annoy the admin** (accepted; unguessable identifier).
